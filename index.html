03

How I work

Read first. Then write.

The same process whether it's a feature in a team repo or a side project at midnight.

01

Read the system

Entities, request flow, security config and background jobs get mapped before a single line changes. No feature starts without a picture of where it fits.

02

Design on paper

Schema, DTOs, API contract and error paths are settled before code — so the implementation is transcription, not decision-making under pressure.

03

Build & document

Controller → service → repository end-to-end, then diagrams and a README, so the next reader never has to guess what I already knew.
